Descripción detallada

Driver WiFi/MQTT basado en comandos AT con RX DMA circular y TX DMA sincronizado.

La arquitectura separa recepción y transmisión en dos canales de hardware: recepción DMA circular permanente para no perder respuestas asíncronas del módulo WiFi, y transmisión DMA sincronizada mediante semáforo para que las tareas FreeRTOS esperen sin ocupar CPU durante el envío físico por UART.

Callback HAL ejecutado al finalizar una transmisión UART por DMA.

Parámetros
[in]huartUART que ha completado la transmisión.

La ISR solo libera el semáforo de transmisión para despertar a la tarea que envió el comando. Mantener el callback mínimo reduce latencia y evita procesar respuestas AT dentro de contexto de interrupción.

◆ search_in_ring_buffer()

int search_in_ring_buffer ( const char * target)
static

Busca una cadena objetivo en los datos recibidos desde la última lectura.

Parámetros
[in]targetTexto que debe aparecer en la respuesta del módulo WiFi.
Valores devueltos
1Se encontró la cadena y se avanzó el índice de lectura.
0La cadena no está disponible en los datos pendientes.

La búsqueda se realiza sobre una copia lineal para poder usar strstr() aunque el DMA esté trabajando sobre un búfer circular. Solo se consume hasta el final de la coincidencia para no descartar respuestas posteriores.

◆ wifi_send_cmd()

wifi_status_t wifi_send_cmd ( const char * cmd,
const char * expected,
uint32_t timeout )
static

Envía un comando AT y espera una respuesta esperada.

Parámetros
[in]cmdComando AT completo, incluyendo terminación \r\n.
[in]expectedCadena que confirma la operación esperada.
[in]timeoutTiempo máximo de espera en ticks del kernel.
Valores devueltos
WIFI_OKLa respuesta esperada se recibió dentro del tiempo límite.
WIFI_ERRORFalló la transmisión o el módulo devolvió ERROR.
WIFI_TIMEOUTNo llegó respuesta concluyente antes del timeout.

La función limpia errores UART y sincroniza el búfer RX antes de transmitir para asociar la respuesta al comando actual. El envío usa DMA para no bloquear la CPU, pero la tarea queda dormida hasta que el hardware confirma el fin de transmisión.
